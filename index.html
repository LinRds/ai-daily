  2. A Fireside Chat with Cat and Thariq from the Claude Code team — Simon Willison
    一句话:Claude Code 两位核心聊设计哲学——给前沿模型加示例已经不是最佳实践,系统提示反而砍掉 80%,少约束、多上下文、靠模型的"判断力"。
    精华摘要
    提示设计反转:对 Fable/Opus 4.8 这类前沿模型,加 few-shot 示例不再最优;Claude Code 系统提示砍掉 80%,少写"别做 X"、多给上下文,让模型自己判断,效果反而更好。
    发布靠内部狗粮:一个功能只有在 Anthropic 内部跑出"员工留存率"(大家真离不开)才对外发,把"好不好用"量化成发布门槛。
    Auto mode 是安全基座:几乎全员用,靠 Sonnet 分类器动态判权限 + 沙箱,数千次评测和红队后,才敢让 Claude 在公开 Slack 频道跑。
    为什么给你:你在调 agent/提示词——"少约束多上下文""砍 80% 提示""先内部留存再发布"都是能直接借用的一手工程判断,还和你"先 eval 再调 prompt"同频。

  3. How Apollo Rebuilt Its AI Assistant on Deep Agents — LangChain
    一句话:Apollo 把 AI 助手从"主管-子代理、每个用例预写流程"换成 Deep Agents 的扁平技能库——agent 自己选技能、自己拼计划,开发周期砍掉 80–85%。
    精华摘要
    架构换血:老的 supervisor+子代理要给每个新用例手写子代理和执行路径,改一次动一次;Deep Agents 用扁平技能库+动态选技能,agent 自主合成计划,与模型厂商解耦。
    可搬的工程法:6 层评估体系(质量维度打分→金测试→实时追踪→聚合指标→周报→用户反馈);点踩进日常分类队列,7 天内点踩>8% 直接判 P1。
    踩坑实录:自研可观测性在多 agent 下"根本看不懂发生了啥",最后靠 LangSmith 拿 thread ID 全链路追踪定位。
    为什么给你:正是你要的"agent 落成产品"骨架——扁平技能库 vs 主管架构的取舍、eval 分层、可观测性怎么搭,几乎每条都能直接抄。
