  1. Evaluating Agents Beyond the First Prompt — Phil Schmid
    一句话:只用"第一轮 prompt"评测 coding agent 严重高估了它——EvoCode-Bench 让 agent 在同一容器里跑多轮迭代(需求不断变),可靠性立刻打回原形。
    精华摘要
    单轮虚高:多轮 vs 单轮,低端模型差约 4 倍(8.4% vs 33.1%),前沿模型也有 1.4–1.8 倍差距。
    排名会重排:Claude Opus 4.6 单轮第一(78.9%),多轮跌到第三(44.0%),被 Opus 4.7、GPT-5.5 反超——"单轮强"≠"扛得住迭代"。
    主要死因是回归:agent 很少因"做不出功能"失败,而是"改坏了已有功能";到第 2 轮,回归类失败占 35%。一个有效招:维护持久需求文档的 agent 成功率翻倍。
    为什么给你:正中"高效验证 AI 代码"+agent eval——评测必须多轮、"回归/一致性"才是真瓶颈;"持久需求文档"和你的 SDD 思路同频。
    新文·2026-07-27🔥 agent eval/多轮/代码 · EN
  2. Benchmarking Opus 5 on SlopCodeBench — humanlayer
    一句话:拿刚发布的 Opus 5 在"分阶段递进需求"的 SlopCodeBench 实测——严格通过率只有 24%,还靠狂写代码(2.9 万行 vs 别家 9 千)解题,93% 的行触发质量告警。
    精华摘要
    今天的前沿模型还不能可靠地独立跑完整个开发周期,真实软件工程仍需人"打方向盘"纠偏。
    更多代码≠更高质量:Opus 5 平均复杂度最低,但靠堆一堆单用小函数(14.9%)实现的"分散",不是深度优化。
    圈复杂度贯穿 8 个 checkpoint 持续上升——长周期里模型有系统性的代码腐化倾向。巧思:强模型搭早期 checkpoint、弱模型接着做,接得住=强模型维护性好。
    为什么给你:和 Phil Schmid 同结论、不同 bench 互相印证;而且是你正在用的 Opus 5 真实 coding 表现,别被单轮 benchmark 的漂亮数字骗了。
    新文·2026-07-27 Opus5/coding eval/context · EN
  3. The harness is all you need (mostly) — GitHub (Burke Holland)
    一句话:别追新工具新技巧,把现有 harness(他直接等同于 Copilot)吃透一次、到处能用;"少即是多"。
    精华摘要
    生产力来自对现有能力的深度理解,不是配置花活;学会一套框架比堆功能强。
    给了可复现的 8 步工作流:原型→规划→实现→审查→迭代→"橡皮鸭"评审的完整周期。
    放权但设边界:开"YOLO 模式"让 AI 自主执行、但跑在沙箱里;并坦白"没人真知道自己在干嘛"。一句戳心:"追求高质量结果是你的责任,没有 AI 能替代你的人类品味。"
    为什么给你:harness 是你一直追的线(接宝玉、Deep Agents)——这篇是"把一套 harness 用到极致"的务实清单;"人类品味决定质量"也呼应 Claude Code 团队那期。
    新文·2026-07-27 harness/工作流 · EN
  4. Import AI 466: The bitter lesson for robotics — Jack Clark
    一句话:新加的 Import AI 首次出场——两条硬料:机器人也吃"苦涩教训"(升级通用模型就白捡能力),以及 AI 已能自导完成"人类要 2–17 周"的编程任务。
    精华摘要
    机器人苦涩教训:Anthropic 只把 Claude 从 4.1 升到 4.7,机器人完成任务提速 20 倍(181 分→9 分 35 秒);Sunday Robotics"扩预训练+少量微调"的 ACT-2 做到 99.1% 成功率——通用模型变强自然带出机器人能力。
    长任务编程(MirrorCode,Epoch×METR):Claude Opus 4.7 用 14 小时、251 美元完成一项"人类要 2–17 周"的任务,25 个目标里 17 个完美解决。
    为什么给你:接你"长任务/自动化开发"主线,也是本期"多轮/长周期评测"主题的第三块拼图;顺便验证新源 Import AI 每周能供硬货。
