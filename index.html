  1. Adversarial Attacks on LLMs — Lilian Weng
    一句话:一张"怎么用对抗性输入操纵 LLM"的全景威胁地图——越狱、token 操纵、套私有/训练数据,以及为什么防守天生难。
    精华摘要
    对抗攻击 = 构造让模型输出你不想要的东西的输入。文本是离散空间,比图像攻击难,但照样可行。
    攻击类型:token 操纵(改词/加扰动)、基于梯度/搜索的越狱、提取预训练数据/私有知识(Carlini)、数据投毒攻训练过程。
    防守是"鞍点问题":没有干净解,默认防护能挡一部分,但对抗者会持续进化——所以要纵深防御,而非指望单点。
    为什么给你:你在做联网/带工具的 agent,这是"威胁模型全景",正好和昨天那次 web_fetch 外泄配着看。
    深读·2023-10 安全/注入/越狱 · EN
  2. Patterns for Building LLM-based Systems & Products — Eugene Yan
    一句话:把 LLM 塞进真产品的 7 个实战模式,按"提性能↔降成本/风险""靠近数据↔靠近用户"两轴排——从 demo 到产品的地图。
    精华摘要（66 min,建议分次读）
    开场戳心:很多问题"做 demo 容易、做成产品极难"(自动驾驶式)。这 7 个模式就是覆盖这段路的工具。
    七模式:Evals(评测,认真做产品 vs 赶工的分水岭)、RAG、Fine-tuning、Caching(省成本/延迟)、Guardrails(防护栏)、Defensive UX(优雅处理出错)、收集用户反馈。
    按两轴组织,并给"模式↔该解决什么问题"的对照,方便你按需取用而不是全上。
    为什么给你:你要把 agent/RAG 落成产品,这是最全的"该上哪些模式、各解决什么"的骨架图,几乎每块都压中你的核心。
    深读·常青🔥 系统设计/RAG/eval · EN
  3. Prompting Fundamentals and How to Apply them Effectively — Eugene Yan
    一句话:提示词的本质=给概率模型"加条件"把输出分布收窄到你要的地方;且强调"先有 eval 再调 prompt",配 Claude API 实操。
    精华摘要（17 min）
    前提铁律:动手做 prompt engineering 之前必须先有可靠 eval,否则你根本没法判断改好了还是改坏了。
    核心心智模型:LLM 是概率模型,prompt = 不断 conditioning——每加一句指令/上下文都在收窄输出(Apple → Apple fruit → apple of my eye)。
    用 Claude Messages API 演示 user/assistant/system 角色等基本功;先把地基打牢再上高级技巧。
    为什么给你:提示词工程的地基,且"先 eval 再调 prompt"和你验证主线同频;示例还正好用 Claude API。
    深读·常青🔥 提示词工程 · EN
