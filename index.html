  1. OpenWiki Brains: Proactive Memory for AI Agents — LangChain
    精华摘要
    把 OpenWiki(原本给代码库自动生成 wiki 的 OSS CLI)扩展成 agent 的通用大脑:连 Gmail / Notion / git / X / HN / web search,把这些信息抓取并结构化成一个本地 wiki 当记忆。
    与内置记忆的区别:内置记忆是被动记住你说过的事实;它是主动去外部源拉取、组织成 wiki、并随时间刷新。
    目的:agent 不必每次会话都把你的项目/兴趣/研究上下文复制进去,而是有个"持久可查"的地方。OSS,0.1.0。
    为什么给你:正中 agent 记忆线,和你 ai_chat 的对话记忆构建高度同构,可直接借它的"wiki-as-memory"架构。

  2. "母病速归"式 AI:号称省 65% Token,实测只有 8.5% — 宝玉
    精华摘要

  3. How I tricked Claude into leaking your secrets(web-fetch 外泄)— Simon Willison
    精华摘要
    Anthropic 的 web_fetch 本来防外泄:只准访问用户亲手输入或 web_search 返回的确切 URL,能挡住"把答案拼到 evil.com?answers= 再访问"这类攻击。
    漏洞(Ayush Paul 发现):web_fetch 还允许访问它此前抓过的页面里嵌的链接→ 造蜜罐站,诱导 agent"一个字母一个字母"顺着嵌套链接走,把数据逐字外带。且只对 user-agent 含 Claude-User 的客户端显示,更难察觉。
    实测偷出用户姓名/城市/雇主。Anthropic 已封堵(禁止 web_fetch 跟进自身抓取内容里的新链接)。典型 lethal trifecta:私有数据 + 读外部指令 + 外发通道。
    为什么给你:你要做联网 / 会调工具的 agent,这就是最现实的prompt injection + 数据外泄风险与防线的活案例。
    Simon · 07-15 Agent 安全/注入 · EN

  1. The Problem is Prompt Debt — Drew Breunig
    精华摘要
    "提示词债":纯英文 prompt 让原型飞快,但作为持久系统行为规范很糟——同义不同词就产生不同输出。
    三症状:①迭代变慢(边界情况/全大写威胁越堆越多,举例 Fable 系统提示把版权指引重复了 6 次);②团队瘫痪(prompt 没人读得懂);③锁死单一模型(4o 上的 hotfix 换个模型就以新方式崩,于是不敢换)。
    结论:自然语言适合一次性任务/对话,不适合定义持久行为;要 model-agnostic 就别手调 prompt → 转向 spec / 测试驱动。
    为什么给你:直接接你的 SDD + 提示词工程——为什么该把行为规范从"堆 prompt"搬到 spec+测试。
    深读·2026-06 提示词工程/SDD · EN
  2. Creating a LLM-as-a-Judge That Drives Business Results — Hamel Husain
    精华摘要
    建 LLM 裁判的落地步骤:①找主领域专家 → ②建多样化数据集 → ③让专家做二元 pass/fail + critique(别一上来搞多级打分)→ ④据此迭代裁判 prompt 直到与专家判断收敛 → ⑤错误分析、分类 trace → ⑥必要时再拆专门化裁判。
    核心洞见:critique(判错理由)比分数更值钱;pass/fail 二元起步最有效;裁判必须持续和人工对齐。
    虽 2024,但 LLM-as-judge 方法论仍是当下标准做法。
    为什么给你:你用 LLM 当裁判去验证产出,这是最实的落地指南,直击「高效验证」链条。
    深读·经典 2024 LLM-as-judge/验证 · EN
