  1. "Drawing" the Mona Lisa with GPT-5.6, Claude, Gemini, and Grok — tryai.dev
    一句话:给四个前沿视觉模型同一套"数字彩铅"去画画,意外测出一个 agent 通病——它们几乎都编辑过头,最终稿反而不如中途的最佳版本。
    精华摘要
    设置:GPT-5.6 Sol / Claude Fable5 / Grok4.5 / Gemini3.6 用同一套画笔(设色/笔宽/压力/涂抹/擦除,还能看自己成果再改),做临摹+开放命题。作者明说这不是客观能力测试。
    最有用的发现:两个临摹任务里,所有模型的最终评分都低于它中途的最佳值——继续编辑=退步;而且高频自评(Gemini 平均 23 次)并没换来更好结果。
    附带:成本悬殊(Fable5 约 $160,是别家 20 倍);各模型工具策略天差地别(Sol 从不单独设色、Grok 65% 调用花在设参数)。
    为什么给你:"agent 不知道该停手、编辑过头把好结果改坏"是长跑 agent 的真通病——比蒙娜丽莎本身值钱;也顺带看到长任务的真实成本差。
    新文·2026-07-21 多模型 eval/agent 行为 · EN
  2. Copilot vs. raw API access: What are you actually paying for? — GitHub
    一句话:GitHub 论证"用 Copilot 比裸调 API 多花的钱,买的不是模型、是整套 harness"——上下文选择、工具调用、重试、预算管控这些流程件。
    精华摘要
    核心框架:token 单价只是表面,真实成本由上下文怎么选、工具怎么调、重试、从 issue 到 PR 的整条路径决定;这些"外围工程"才是收费点。
    数据主张:称在多个基准上"任务解决打平、但大多数配置下用更少 token";并给组织级额度池、预算追踪、BYOK(自带 key、留工具链转走计费)。
    诚实提醒:这本质是 GitHub 为自家定价辩护、缺第三方对比,当立场文看。
    为什么给你:它把"harness 的价值=上下文管理+工具+重试+预算",正好和宝玉那篇"省 token 靠上下文/缓存、不是压缩措辞"、昨天 Deep Agents 串成一条线;判断自建 vs 买工具时有用。
