  1. Controlling Reasoning Effort in LLMs — Sebastian Raschka
    一句话:怎么给推理模型加"用多大力气想"的档位——GPT-5.6 每个尺寸都带 5~6 档 reasoning-effort,本质是"质量 ↔ token/延迟"的旋钮。
    精华摘要
    推理模型(o1/R1 起)已成模型发布标配;上周 GPT-5.6 家族三个尺寸、每个约 5~6 档 reasoning-effort 设置。
    "reasoning"别按字面理解成像人推理——指模型先输出一串中间步骤再给答案;本文讲怎么做出"带多档 effort 模式"的这类模型(可独立阅读)。
    实际意义:effort 档 = 在答对率和花的 token/时间之间显式取舍,低档快而省、高档慢而准。
    为什么给你:直接接你"低延迟应用层"——聊天场景按需选 effort 档,是控 TTFT / token 成本的一手旋钮。
    Raschka · 07-18 推理/延迟成本 · EN

  1. Task-Specific LLM Evals that Do & Don't Work — Eugene Yan
    一句话:现成通用 eval 大多没用(和你应用表现几乎不相关);按任务类型照着挑真正管用的指标就行。
    精华摘要（33 min 长文）
    核心痛点:off-the-shelf eval 和应用性能几乎不相关、区分度差,产线不能用。他直接给一份"分任务、实测有用"的指标清单。
    分类→recall/precision/ROC-AUC/PR-AUC + 看分布分离;摘要→NLI 查一致性、reward model 查相关性、长度;翻译→chrF/BLEURT/COMET;版权→逐字/近似复现;毒性→毒性生成占比。
    末尾:人工评估的角色 + 怎么校准评估门槛(收益 vs 风险),以及避免 Innovator's Dilemma。
    为什么给你:你验证/eval 主线的"工具箱级"参考,给自己任务挑指标时照单抓药,少走弯路。
    深读·常青 eval/指标 · EN
  2. Two Beliefs About Coding Agents — Drew Breunig
    一句话:①高手喂给 coding agent 的隐性直觉被严重低估(你看不到大佬的 prompt);②大家晒的多是惊艳个人工具,不是能长成的产品。
    精华摘要
    信念一:名人晒"几周没写代码、丢给 Claude Code 就成了"——但你没看到他们的 prompt。作者看过大量 prompt,断定高手的 prompt 远比普通人具体、给的引导多,且多轮交互里凭直觉不断校正。"agent 让人人会编程"被高估。
    信念二:晒出来的多是 StreetPass 那种精巧个人工具,离"大写 P 的产品"还很远。个人能跑 ≠ 能交付给别人。
    为什么给你:接你 agent 开发 + SDD——为什么"隐性引导/规格"才是 agent 出活的关键,以及别把 demo 当产品。
    深读·2026-02 Agent 开发/认知 · EN
